# Aggregate feature reports

Issue #444 adds Administration → Features. Its fixed queries return totals only; there is no account filter, free-form query or content drill-down. Existing-record counts reflect retained records, using UTC creation/acceptance/join dates, except weigh-ins use the recorded weigh-in day. Active plans, leaderboard opt-in and registered push devices are labelled current state. Food-source provenance is not a reliable logging-method history. Optional forward-only action labels on new food rows distinguish describe, search, barcode, photo, recipe, copy and manual actions; older rows/clients stay unknown. Labels are not added to model context or nutrition source references. They are immutable on nutrient edits and ignored on replay. Kit legacy rows are retained conversations, not a complete visit history.

Counts for fewer than three contributors are hidden before serialization, including uses/rates/comparisons. A trend is hidden if any bucket is small, so the total cannot reveal its remainder. Funnel counts also hide a complement smaller than three; steps are independent and week2 excludes immature cohorts. These controls reduce small-cell disclosure; they are not differential privacy or a guarantee of anonymity.

New collection defaults OFF. `KINETTA_FEATURE_METRICS=1` enables fixed feature counters and two first-setup dates. **Owner approval of the privacy-policy wording is required before enabling it.** This implementation does not change any runtime setting. Review `site/content/privacy.md` and generated `site/privacy.html` in the same PR. Only individually opted-in participants contribute to record reports and the signup cohort. New participants start off; Welcome and Settings provide the explanation and explicit switch; Settings also provides withdrawal. Setup steps completed before participation remain unknown. Turning participation off immediately stops new collection and excludes their retained records; prior anonymous counters remain until expiry.

Authenticated opens carry one fixed feature enum, never a URL, account ID or text. The backend supplies the owner and UTC day. Daily random HMAC keys are feature-specific, limited to the current day and removed at midnight by collection/read plus a minute cleanup worker. The anonymous `(feature, day, people, opens)` counters retain13 calendar months, without identifiers. Repeat opens are coalesced for30seconds. Successful counter requests bypass account-linked API diagnostics; failed requests and other API diagnostics retain their existing behavior. Across days, sums are labelled user-days from visible days only; hidden days never contribute to public report sums. A previous12-month comparison is unavailable with13-month retention.

First welcome completion and Health permission-screen completion store only a UTC day on the existing private profile, cleared on account deletion. Historical setup is unavailable and never backfilled. Health setup does not prove that Apple allowed any read category. Anonymous daily totals cannot be linked back to a deleted account and remain until expiry. New admin counter/key/state tables enable RLS and grant no reader access.


## App Store release requirements

Before enabling this feature, update the checked App Store Connect answers for Usage Data → Product Interaction used for Analytics, linked to the user, and review the existing User ID Analytics purpose. Authentication, temporary matching keys and account-linked setup/action labels mean this collection cannot be described as entirely unlinked. The optional per-person permission does not replace disclosure. Existing record-derived Health/Fitness purposes must also be reconciled in the App Store review; no health readings, route geometry or private text enter these reports. This PR does not change Connect answers or enable collection.

Apple defines these categories and linking in [App privacy details](https://developer.apple.com/app-store/app-privacy-details/), requires consent and accessible withdrawal in [Review Guideline5.1.1(ii)](https://developer.apple.com/app-store/review/guidelines/#data-collection-and-storage), and allows [privacy-answer updates](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy) without submitting a new binary. First-party analytics alone does not invoke Apple's cross-company advertising tracking definition. No Apple approval is claimed.
