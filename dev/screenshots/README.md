# Fictional product captures

`scenes.json` is the shared website/App Store capture list. Each entry supplies a stable scene name, the app route (or the demo-record resolver in `take.js`), and any setup action. The same clean data comes from `dev/demo/seed.py`, `stage.py` and `coach.sql`. Activity uses seven accepted fictional friends across running, riding and walking, plus a separate pending request. The feed has mapped routes, reactions and comments. For the Friends screenshot, `take.js` adds a labelled, fictional 25-mile achievement stand-in beside Morgan's mapped ride; the app renders its real achievement-moment card, but the stand-in does not come from server milestone records. The Trail Crew group derives its 70% goal from seven recorded sessions and shows member avatars. Food includes a five-entry Nutrition day and a Kit chat for “2 eggs, toast, black coffee”; all nutrition values are made-up fixture data, and no provider is called.

The Home selling-page scenes show the fitness/fatigue/form trend, the combined weekly training/food review, and a Kit answer to “Why was my pace down this week?” The answer is a screenshot-only stand-in calculated from the throwaway account's demo runs and training-load records; it never calls a model or reads non-demo data. Smaller supporting shots show a matched route with its best time, 5K personal records and the training/food calendar heatmap. The Home Food and Friends sections use `nutrition-day`, `describe`, `friends-feed`, `friends-group` and `friends-me`; the app captures use the Home | Progress | Track | Nutrition | Me navigation merged in #702.

Some headless Linux browsers do not include emoji fonts. Feed captures render the app's three reaction values with the bundled matching Twemoji artwork so the screenshots show the same clap, star-struck and mind-blown emoji as the UI. Twemoji 15.1.0 by Twitter, Inc. and contributors is licensed under CC BY 4.0: https://github.com/jdecked/twemoji/tree/v15.1.0.

Start an isolated disposable Compose project with `compose.standin.yml`, load the fixtures, then run `take.js <png-directory> <base-url>` and `to_webp.py <png-directory> site/assets/shots`. Set the operator-approved map variables explicitly: the capture script blocks the public OSM tile endpoint. The website workflow reads only the published public `/api/map-config` through `map_env.py`, with no account or private runtime access. For localhost captures, its range-request relay uses the published app origin and adapts response CORS to localhost; archive bytes and rendering stay unchanged. No production CORS setting is changed. A visible map-load failure stops capture/publication. Food estimates, product lookup and prepared Kit reviews use labelled-in-documentation stand-ins, with no live AI or food-provider request. The screenshots show actual implemented browser controls and fictional records; they do not demonstrate model accuracy.

Website PNGs are whole393×852 browser viewports at2× (786×1704). The converter makes both393×852 `-1x.webp` and786×1704 `.webp` files, preserving the complete screen. Both themes use the same framing. `manifest.json` records the source revision and capture time; an open page refreshes each srcset candidate while preserving its density descriptor.

These website captures draw a simulated status/home bar and use browser safe-area substitutions. **They are not native iPhone or App Store evidence.** For #415, reuse the scene names, routes and fictional fixtures when capturing the actual6.9-inch UIKit Simulator at1320×2868. Do not resize these browser files into store screenshots. Native compilation, signed upload, App Store privacy answers, review and physical-device acceptance are separate release steps.
