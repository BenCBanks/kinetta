# Fictional product captures

The Homepage screenshot job prepares nine exact byte ranges (533,070 bytes) from the approved versioned archive before browser capture. `archive-ranges.json` records the ranges used by the fictional map scenes. Preparation requires a fresh job-local directory, an exact approved URL, valid HTTP 206/Content-Range/length and one consistent strong ETag; redirects and invalid responses are refused. Limits are two concurrent reads, one transient retry, 30 seconds per read, two minutes total, 64 ranges/4 MiB total and 256 KiB per range. Only validated real bytes enter the temporary cache; it is not uploaded or reused between jobs and is removed in cleanup.

`take.js` enables this transport only when `KINETTA_CAPTURE_ARCHIVE_CACHE` names the prepared directory. Cache hits are logged; misses retain the existing upstream relay and failure behavior. Archive changes require a refreshed reviewed range plan. Cold preparation timings remain separate from warm screenshot timings: this is screenshot reliability evidence, not production cold-map performance evidence. App/native source, the app's eight-second source timeout, and all required/visible/loaded/idle/opaque/unavailable map assertions remain unchanged. Local captures without the variable keep the uncached path.

`scenes.json` is the shared website/App Store capture list. Each entry supplies a stable scene name, the app route (or the demo-record resolver in `take.js`), and any setup action. The same clean data comes from `dev/demo/seed.py`, `stage.py` and `coach.sql`. Activity uses three accepted fictional friends, plus a separate pending request; it shows a populated feed rather than a new-account discovery prompt. The Food story includes Add food, Nutrition, Insights and recipes. `kit-food-chat-confirmed` stages a typed fictional lunch, then confirms it through the app UI; the sample nutrition is stand-in data, not an AI result. Retake after app design changes merge.
