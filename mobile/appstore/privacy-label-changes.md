## Retention and choices — do not copy older temporary-chat wording

- **Saved conversations:** the server keeps questions and checked answers until deletion; visit cleanup after24hours does not expire saved threads. Reopening/reading saved history does not require another AI request. History is server-gated, not an unconditional promise for every self-hosted installation. Legacy temporary chats can still end on leaving; unknown legacy answer provenance is quarantined from display/replay rather than presented as verified. Sources: `kit_history.enabled`, `preserve`, `prune`, `kit_history_api.listing/messages`, migration119 in `app/db.py`.
- **Deletion/export:** Kit supports deleting one or all saved chats, and account export includes threads/turns/memories. Deleting a chat does not delete separately saved memory. Removing source data or revoking relevant sharing invalidates affected saved answers; questions remain. Regranting consent does not restore erased answers. Account deletion removes the account's content; policy backup/operational-retention exceptions still apply. Sources: `kit_history.remove`, `kit_history_api.erase`, `api_mydata.py`, `api_account.py`, migration119 source/consent triggers and `site/content/privacy.md`.
- **Memory:** at most12 short notes; each note is bounded to400characters. Current queries exclude notes older than180days since update, and the memory read endpoint deletes expired notes on access. Do not promise an exact midnight six-month purge. Turning memory off deletes the saved notes; individual/all deletion and manual add/edit are available. Deleting chats and turning AI off are not substitutes for the memory deletion controls. Source: `kit_memory.context/remember/save`, `kit_thread.memory_settings/memories`, `app/static/kit.js` `memorySettings`.
- **Provider context:** only bounded permitted recent turns from the active conversation and up to12 permitted notes are added to the relevant request. Not every saved chat is sent. Prior chart payloads are excluded from replay history; current chart tools fetch their own records. Health/Garmin consent gates still apply. Provider retention is separate from Kinetta deletion: confirm actual provider/fallback, service tier, retention/training terms and the explicit sharing explanation before release. Sources: `kit_thread.generate` context assembly, `kit_coaching.question_context`, `coach_chat.py`, `ai_access.py`, `site/content/privacy.md`.
- **Metrics:** current-day matching salt/digests are cleared by cleanup; anonymous daily totals retain13calendar months and cannot be tied back for deletion afterward. Account-linked method labels live with food records and setup dates with the profile until deletion. Existing source/policy records say hosted metrics were enabled for all accounts, without an individual opt-out; this audit does not verify today's runtime switch. Self-hosted collection defaults off. Sources: `admin_features.cleanup`, `docs/admin-features.md`, policy How we improve Kinetta.

## Release decisions that remain open

1. **Health-derived analytics:** reconcile the submitted configuration with Apple's consent, repurposing and Health restrictions ([Guidelines5.1.1–5.1.3](https://developer.apple.com/app-store/review/guidelines/#privacy)). The current code's switch is operator-wide, with no per-person withdrawal. Selecting Analytics, first-party processing or hiding counts below three is not evidence of an exception. Owner must document an eligible approved configuration or obtain a scoped implementation change before submission; this Draft changes no switch or data flow.
2. **AI sharing:** Apple explicitly addresses personal data sent to third-party AI in [5.1.2](https://developer.apple.com/app-store/review/guidelines/#data-use-and-sharing). Check the actual pre-send permission text, named configured partners and retention against the selected build; memory on/off and Health permissions are separate controls. Do not claim zero provider retention or guaranteed medical safety from a disclaimer.
3. **Policy/manifest alignment:** existing policy already describes saved chats,12 notes, edits/deletion via What Kit remembers and metric retention. Its “older than six months are removed” is a simplified description of180-day filtering/access cleanup; use the precise wording above in review notes, and consider tightening that sentence in a separately assigned policy edit. The manifest already contains Product Interaction/A, User ID/A and Health/Fitness/A/P, plus Other User Content/F/P. No manifest change is required solely for the new UI/storage details. Confirm final Connect categories/purposes; contact-hash classification and partners remain open from the full audit.
4. **Current Groups and policy:** Groups/challenge cutover is merged. Per-challenge sharing inherits group/legacy choices, is gated by Share achievements, and ordinary permitted totals do not have a three-member minimum; recap paths retain their separate threshold. Current invite UI starts Share my total on; old omitted-field requests default off. Group workout totals exclude Only me activities; standalone challenges can include them without revealing activity details. See the full inventory for source/default/rejoin rules. Reconcile the website policy’s older group-threshold and generic-name wording before submission; do not claim this docs PR changes policy or runtime.
5. **Names and imports:** Name collection includes required first/last name, with first-only display to ordinary non-friends. Merged web archive staging adds account-linked import/status/reminder records and staged user content; it does not mean native ZIP receipt/guided/background import has shipped. Existing broad categories cover these flows; confirm exact Connect classification and retention against the selected configuration.
